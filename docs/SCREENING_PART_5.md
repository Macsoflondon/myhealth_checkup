# Screening, part 5 — 22/11/2026

## Implemented

- Added byte-identical app and Edge article decoders, with parity tests. All 18 requested named entities, decimal/hexadecimal numeric entities and up to three decoding passes are covered. Unknown entities remain unchanged; invalid Unicode scalar values are handled safely.
- App aggregation uses the shared decoder. The public article read also decodes titles/excerpts so existing encoded rows no longer appear literally on preview guide cards or image alternative text. Stored rows are not hand-edited.
- Added a bounded Edge repair helper selecting title **or** excerpt candidates with `title.like.%&%;%,excerpt.like.%&%;%`, stable ID ordering and a maximum of 500 candidates. It updates changed title/excerpt fields only, preserving null excerpts and dates. Mocked tests do not write to the database.
- Added EDGE index link/date helpers, filtering to unique on-provider biomarker article URLs and preserving unavailable publication dates.
- Shopify provider article images now use requested-width WebP URLs, width-descriptor candidates and card-slot sizes. Other hosts remain unchanged. Lazy loading, async decoding, width/height and provider-image error fallback are retained.
- Bundled illustrations have 480/768px WebP candidates generated by a Vite build-only Sharp plugin. Original 1024px artwork remains the largest candidate. Sharp is never imported into Worker or browser code; both lockfiles are reconciled.
- Showcase queries no longer select descriptions or biomarker arrays. Both showcase presentations use the already-prefetched details map for the rendered fields.
- Three blog article breadcrumb trails now have 24px-tall link areas; text remains 14px.
- Browser verification exposed pre-existing AutoReveal mutations that raced deferred hydration. The same fade/rise animation now uses Web Animation effects instead of React-owned DOM attributes; the fresh homepage browser run has zero hydration warnings and no page errors.
